# 社交平台监测（公开索引模式）

本模块在“社交平台监测”页面管理监测对象，仅处理 X 与 Facebook 的公开单帖。无需平台账号、Cookie 或账号池，也不调用付费平台 API；不会读取评论、私密内容或搜索引擎未收录的帖子。

## 来源与覆盖边界

- X：先查询 Social Searcher 的 X 专用可编程搜索页，再查询 Awesome OSINT List 收录的 X 专用搜索页。
- Facebook：查询 Awesome OSINT List 收录的 Facebook 专用搜索页。
- 这些页面都基于 Google 索引，不能当作相互独立的事实来源，也不能保证实时或全量覆盖。每个搜索词只读取第一页；出现验证页、限流或无可读结果时记录来源异常，不尝试绕过。
- 只接收 X/Facebook 单帖 URL，拒绝主页、群组和其他域名。X 通过公开嵌入接口补全文字；Facebook 只读取匿名可见的公开元数据，可能只有摘要。原帖不可访问时，搜索摘要最多形成 `unverified_search_hit`，不会冒充已核实正文。

## 使用方式

管理员在页面创建监测对象，填写名称、企业别名、风险词和最多 4 组搜索词。宁德时代示例按钮只填表，不会自动保存或声明发现事件。保存并启用后，API 进程每分钟检查到期任务，默认每 120 分钟执行一轮；也可由管理员点击“立即扫描”。系统用数据库租约避免重叠扫描，重启后继续依据 `next_scan_at` 调度。

普通账号需由管理员分配 `social_monitoring` 模块权限才可查看和核验；创建、修改及手动扫描仅管理员可执行，服务端同样校验权限。结果按监测对象、平台和帖子 ID 去重，保留首次/最近发现时间、来源模式、扫描状态和人工判断。`candidate` 仅表示原帖文字或公开元数据同时命中企业及风险词，不是安全事件确认；“有独立佐证”需要分析员提供非社交平台的 HTTPS 证据链接和备注。帖子正文与搜索摘要只在扫描时用于匹配，不落库；仅保留链接、脱敏标题和命中词等安全元数据。打开线索详情时可按需重新读取公开页面，临时显示最多 600 字符的脱敏预览；Facebook 的公开元数据会明确标为“非全文”，该预览不入库且接口禁止缓存。

后端依赖现有 `playwright` 安装及可用的 Chromium；Windows 本地若缺少 Playwright Chromium，会使用已安装的 Chrome。无法启动浏览器会留下失败扫描记录并在 15 分钟后重试。模块不会自动发送通知或向外部平台发布内容。

API 前缀：`/api/social-monitoring`。主要接口为 `status`、`watchlists`、`watchlists/{id}/scan`、`watchlists/{id}/hits`、`watchlists/{id}/scans`、`hits/{id}/preview` 和 `hits/{id}/review`。
